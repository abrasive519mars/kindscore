## 1. `scripts/seed.ts` — the demo world, generated by the real engine

Idempotent (`--env <file>`; refuses to run without `--yes` against a non-local URL). Order:

1. **Wipe** previous seed: every auth user with `@kindscore.app`, every draw (cascades entries, results, verifications), their payments/donations (cascade via profiles). Charities come from `supabase/seed.sql` and are left alone.
2. **Accounts** via the Auth admin API (`email_confirm: true`, password from `SEED_PASSWORD`): `admin@kindscore.app` (role admin); `priya@` (yearly, 15% to Udaan, scores `28 33 31 36 29`); `raj@` (monthly, three scores — ineligible); `anita@` (lapsed on 1 Sep, five scores, one **paid** win in June); `member001…member300@` (80% monthly / 20% yearly, charities spread across all seven, 10–30% shares, five scores each on a bell curve around 30, distinct dates in the last 30 days).
3. **Subscriptions** `source = 'seed'` (active, period end +1 month/year); anita `lapsed`.
4. **Payments** one per active member per month **June–September** (`paid_at` = the 3rd), split by `splitPayment` at the member's share — the ledger trigger fills `charity_contributions`; reports, charity totals and the landing proof strip become real.
5. **Draws** June (random) → July (algorithmic) → August (random), each **through `DrawService.simulate` + `publish`** signed in as the admin (the RPCs check `is_admin()`, so the seed logs in like the app does). The rng is _steered_: a helper computes, pick by pick, the `r` that selects a target number given the drum's current weights, so the draw is the engine's own sampler landing on chosen numbers. Chosen so that no month has a five-match (the jackpot ladder climbs Jun → Jul → Aug → Sep), August = `33 12 29 36 41` (Priya's three, exactly the landing story), `member017` holds four of August's numbers, `member012` three, anita three of June's.
6. **Verification states** through `WinnerService` on each member's own session: anita June → proof → approved → **paid**; member017 Aug → proof → approved → paid; member012 Aug → proof **submitted** (pending review); Priya Aug → **awaiting proof**.
7. Prints a summary table (accounts, pool per month, jackpot carried, winners) and the demo credentials.

Local proof: `pnpm db:reset && pnpm seed` → `pnpm test:int` still green (the suites create their own users) → the walkthroughs still pass.

## 6. Decisions made here

- **[decision] Demo history is generated, not typed.** The three published months come from the real engine with a steered random source, so every figure on every page is internally consistent — and the evaluator's own September draw is untouched.
- **[decision] Seeded subscriptions are marked `seed`** and never touch Stripe; the evaluator's own signup on the live site is the proof that Stripe works.
- **[decision] Demo accounts live at `@kindscore.app`** (Supabase Auth refuses reserved TLDs like `.test`); no mail is ever sent (confirmation is off).
- **[decision] The README is the only place setup, features and decisions are written in full**; TESTING.md, the notes and the PDF are built from or link to it.
